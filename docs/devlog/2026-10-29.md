## 当前需要注意的问题

### 注册关闭判断仍有一个边界问题

`blog/views.py` 里的 `ALLOW_REGISTRATION` 判断目前位于注册逻辑的 POST 分支之后：

```python
if request.method == "POST" and form.is_valid():
    user = form.save()
    ...
    return redirect("blog:list")

if not settings.ALLOW_REGISTRATION:
    raise Http404
```

所以现在：

- 匿名 GET `/account/register/` 会被中间件拦截或返回 404；
- 但如果在 `PRIVATE_SITE=False` 且 `ALLOW_REGISTRATION=False` 的情况下直接 POST 注册表单，仍可能先创建用户。

正确做法是把判断放到 `register()` 函数最开头：

```python
def register(request):
    if not settings.ALLOW_REGISTRATION:
        raise Http404

    if request.user.is_authenticated:
        return redirect("blog:list")
```

私密站点当前靠中间件挡住了匿名访问，所以线上表现正常；但这个后端漏洞需要在恢复公开前修掉。

## 今天学到

- 中间件适合统一拦截未登录请求，必须放在认证中间件之后。
- 隐藏 HTML 注册链接只是界面层，后端仍要拒绝注册请求。
- 关闭注册的判断必须放在函数最前面，不能放在任何成功分支之后。
- Session/Cookie 维持登录状态，`request.user.is_authenticated` 是访问控制的核心。
- Nginx 直接提供 `/media/`，页面登录保护不等于图片直链完全私密。
- 环境变量开关可以在不重写模板的情况下切换公开/私密模式。
