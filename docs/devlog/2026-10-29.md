## 已修复的边界问题

注册关闭判断原来位于注册视图的 POST 分支之后，可能被直接 POST 绕过。

现在已把判断移到 `register()` 最前面：

```python
def register(request):
    if not settings.ALLOW_REGISTRATION:
        raise Http404
```

并增加了直接 POST 注册表单的测试，确认不会创建用户。

### 主题按钮没有反应

第一次实现时把 DOM 方法写成了：

```javascript
document.getElementByID("theme-toggle")
```

正确方法是大小写敏感的：

```javascript
document.getElementById("theme-toggle")
```

修复后本地提交 `e29f5da`。服务器拉取代码后还需要重新执行：

```bash
docker compose up -d --build
```

因为只 `git pull` 不会自动更新正在运行的容器和 Nginx 提供的静态文件。

## 今天学到

- 中间件适合统一拦截未登录请求，必须放在认证中间件之后。
- 隐藏 HTML 注册链接只是界面层，后端仍要拒绝注册请求。
- 关闭注册的判断必须放在函数最前面，不能放在任何成功分支之后。
- Session/Cookie 维持登录状态，`request.user.is_authenticated` 是访问控制的核心。
- Nginx 直接提供 `/media/`，页面登录保护不等于图片直链完全私密。
- 环境变量开关可以在不重写模板的情况下切换公开/私密模式。
- 主题切换可以完全在浏览器端完成，不需要数据库或 Django 视图。
- DOM API 方法名区分大小写，`getElementById` 不是 `getElementByID`。
- Git 拉取代码后，正在运行的容器和静态文件不会自动更新，需要重新构建。
- 修改静态文件后要检查 `collectstatic` 结果，并在浏览器强制刷新。
