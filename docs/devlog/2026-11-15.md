## 遇到的问题

### 1. 关于页模板 block 拼写错误

`about.html` 中曾写成：

```django
{5 block content %}
```

正确应为：

```django
{% block content %}
```

错误导致第 24 行的 `{% endblock %}` 找不到对应 block。

### 2. 关于页侧边栏显示“暂无文章”

`about` 视图最初只渲染模板，没有传入侧边栏上下文。后来改为：

```python
return render(request, "blog/about.html", {
    **cached_sidebar_context(),
})
```

最新文章、分类和归档恢复正常。

### 3. 关于文字看起来“不知道从哪里来的”

关于内容不在 Python/HTML 源码里，而是保存在数据库：

```text
SiteSetting.about
```

模板通过：

```django
{{ site.about|linebreaks }}
```

显示数据库内容。因此 PyCharm 搜索不到，Git 也不会携带这段文字。

### 4. 服务器 Git 拉取超时

普通 `git pull` 曾出现 SSL timeout；使用 HTTP/1.1 后成功：

```bash
git -c http.version=HTTP/1.1 pull
```

后续可以在服务器固定：

```bash
git config --global http.version HTTP/1.1
```

## 今天学到

- 代码由 Git 管理，后台填写的业务数据由数据库管理。
- Django 模板的 `{% block %}` / `{% endblock %}` 必须正确配对。
- context processor 可以让所有模板自动拿到站点配置。
- 新增页面时不仅要写模板，还要把页面需要的侧边栏上下文传进去。
- 静态头像和 favicon 需要通过 `collectstatic` 更新到服务器。
- 修改服务器数据库内容后不需要重建镜像；修改代码和静态文件通常需要重新构建。
