## 遇到的问题

### 1. 本地没有 Docker

`docker --version` 提示找不到命令，所以今天无法在 Windows 本机实际构建镜像。

处理方式：

- 先写好 Dockerfile；
- 让 GitHub Actions 的 `docker` job 在 Ubuntu 上验证构建；
- 真正部署时也可以直接在 Linux 服务器上构建。

### 2. 还没有 GitHub 远程仓库

`git remote -v` 目前为空，所以 CI 配置写好了，但还没有推送到 GitHub 运行。

处理方式：

- 先把仓库推到 GitHub；
- 之后每次 push 都会自动运行 CI。

### 3. Codex 沙箱里的临时目录权限

在 Codex 沙箱里运行测试时，附件测试访问系统临时目录失败：

```text
PermissionError: [WinError 5]
```

这是执行环境的目录权限限制，不是项目逻辑错误。测试总数为 28 个；最终结果以本机终端为准。

## 今天学到

- 代码里不能硬编码生产密钥，密钥应通过环境变量注入。
- `DEBUG=False` 后必须显式配置 `ALLOWED_HOSTS`、Cookie、HTTPS 和 HSTS。
- `STATICFILES_DIRS` 是源目录，`STATIC_ROOT` 是 `collectstatic` 的输出目录。
- 健康检查接口用于让负载均衡器或监控确认应用还活着。
- Dockerfile 让运行环境可复现，CI 可以在每次 push 时自动检查。
- GitHub Actions 只有在仓库有远程地址并 push 之后才会运行。
