# 服务器入门：原理、类型与选择

## 1. 服务器到底是什么

“服务器”可以指两样东西：

1. **硬件**：一台长期开机、连接网络的计算机；
2. **软件/服务**：在这台机器上监听端口、响应请求的程序。

你访问博客时，大致发生这些事：

```text
浏览器输入域名或 IP
  → DNS 把域名解析成 IP（用 IP 访问时跳过）
  → 浏览器连接服务器的 80/443 端口
  → Nginx 接收 HTTP/HTTPS 请求
  → Nginx 把动态请求转发给 Gunicorn
  → Gunicorn 调用 Django
  → Django 查询 SQLite，渲染页面
  → 响应沿原路返回浏览器
```

服务器不是“云里的一台魔法机器”，本质上就是一台运行 Linux、保持联网的电脑。

## 2. 服务器在我们的项目里负责什么

- 运行 Django/Gunicorn 进程；
- 用 Nginx 接收公网请求；
- 保存 SQLite 数据库；
- 保存用户上传的图片；
- 提供静态 CSS 文件；
- 记录日志、处理 HTTPS、限制端口访问；
- 保持进程在关机/重启后自动恢复。

## 3. 常见服务器类型

### 3.1 物理服务器 / 独立服务器

整台物理机器归你使用。

优点：

- 性能和控制力最强；
- 适合高负载、特殊硬件。

缺点：

- 贵；
- 需要自己维护硬件；
- 对个人博客来说过度。

### 3.2 VPS / 云服务器（推荐）

VPS 是把一台物理服务器虚拟成多个独立虚拟机。阿里云 ECS、腾讯云轻量应用服务器都属于这一类。

优点：

- 有完整 Linux 权限；
- 可以安装 Docker、Nginx、数据库；
- 图片和数据库可以持久保存；
- 最接近真实生产环境，学习价值高；
- 价格对个人项目通常可接受。

缺点：

- 需要自己配置系统、防火墙、Nginx；
- 需要自己备份和更新；
- 配置错误可能导致服务不可用。

适合本项目：**是**。

### 3.3 PaaS（平台即服务）

例如 PythonAnywhere、Render、Railway、Heroku。你提交代码，平台负责运行环境和部分运维。

优点：

- 上手快；
- 不用自己装 Nginx；
- 适合快速做演示。

缺点：

- 对 Python/框架版本有限制；
- 免费套餐通常会休眠或限流；
- 上传图片可能丢失，因为磁盘可能是临时的；
- 自定义 Nginx、系统服务和网络配置的自由度较低。

适合本项目：可以做临时演示，但不适合长期保存图片。

### 3.4 Serverless / 函数计算

代码按请求触发运行，不维护长期服务器。

优点：

- 不用管理服务器；
- 低流量时可能很便宜。

缺点：

- 冷启动；
- 不适合长期运行的 Gunicorn；
- 文件系统和媒体持久化复杂；
- 对传统 Django 项目改造较多。

适合本项目：不推荐。

### 3.5 共享主机

多个网站共享同一台服务器和运行环境。

优点：

- 便宜；
- 通常有控制面板。

缺点：

- 权限有限；
- 不能自由安装 Docker/Nginx；
- Python 版本和依赖受限。

适合本项目：不推荐。

### 3.6 家用电脑 / NAS

优点：

- 硬件成本低；
- 数据在自己手里。

缺点：

- 家庭网络、公网 IP、断电和稳定性问题；
- 安全暴露风险高；
- 不适合作为正式作品地址。

适合本项目：可以本地演示，不建议公网部署。

## 4. 方案对比

| 类型 | 控制力 | 成本 | 维护成本 | 媒体持久化 | 适合本项目 |
| --- | --- | --- | --- | --- | --- |
| 独立服务器 | 最高 | 高 | 高 | 好 | 过度 |
| VPS / 云服务器 | 高 | 中低 | 中 | 好 | **最推荐** |
| PaaS | 中 | 低到中 | 低 | 取决于平台 | 可做演示 |
| Serverless | 低 | 按量 | 低 | 复杂 | 不推荐 |
| 共享主机 | 低 | 低 | 低 | 一般 | 不推荐 |
| 家用电脑/NAS | 高 | 低 | 高 | 好 | 仅本地 |

## 5. 本项目推荐配置

- Ubuntu 22.04 或 24.04 LTS；
- 2 核 CPU；
- 2GB 内存；
- 40GB 左右磁盘；
- 开放 22、80、443 端口；
- 先使用公网 IP，不急着买域名。

地域选择：

- **中国大陆地域**：访问通常更快，学生优惠可能便宜；以后绑定域名可能需要 ICP 备案；
- **香港/新加坡等地域**：一般不需要备案，但延迟和价格可能不同。

## 6. 部署时各组件的分工

| 组件 | 负责什么 |
| --- | --- |
| Nginx | 接收 80/443、HTTPS、静态文件、反向代理 |
| Gunicorn | 运行 Django WSGI 应用 |
| Django | 业务逻辑、模板、ORM |
| SQLite | 保存文章、评论、用户等数据 |
| media | 保存用户上传图片 |
| staticfiles | 保存 collectstatic 收集的 CSS 等文件 |
| Docker | 固定运行环境 |

## 7. 安全底线

- 不要把服务器密码、私钥、`.env` 发到聊天或提交到 Git；
- 优先使用 SSH 密钥登录；
- 只开放必要端口；
- 生产环境 `DEBUG=False`；
- 使用强随机 `DJANGO_SECRET_KEY`；
- 配好 HTTPS 后再开启强制 HTTPS；
- 定期备份数据库和 `media/`；
- 定期更新系统和依赖。

## 8. 面试时可以怎么讲

你可以把部署链路讲成：

```text
Nginx 负责公网入口和静态资源，
Gunicorn 负责运行 Django，
Docker 固定运行环境，
SQLite 和 media 通过挂载目录持久化，
GitHub Actions 在每次提交时验证测试和镜像构建。
```

这比只说“我买了个服务器”更能体现工程理解。
